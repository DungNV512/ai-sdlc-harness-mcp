# Use KB Skill

This repo's knowledge base is four plain directories plus one file on disk — no
database, no external index server. This skill is the map: what lives where,
what each frontmatter field means, and which of the other five skills to
reach for.

## Directory layout

```
docs/raw/       Immutable, one-file-per-upstream-page/issue mirror.
                192 Confluence pages as of 2026-07-28. Keyed by page_id
                (Confluence numeric ID or Jira issue key), never by 
                filename/slug — see docs/raw/SCHEMA.md's page-ID-keying 
                contract. Written only by bin/ingest-confluence.sh / 
                bin/ingest-jira.sh.
                Origin: ingested.

docs/wiki/      Compiled, curated knowledge in OKF v0.2 format, grouped by 
                topic: docs/wiki/<topic>/<topic>-overview.md (or other artifact 
                name). 21 artifacts as of 2026-07-28 (one sidecar excluded per 
                producer convention). One clear per-topic entry point each, 
                meant for a human to actually read (unlike raw/'s near-duplicate 
                mirrors). wiki/index.md is the generated table of contents; 
                wiki/log.md is the change history. Sidecars like 
                auth/auth-overview.recompiled.md are review working copies, not 
                published concepts.
                Origin: ingested (from docs/raw/ upstream_refs).

docs/okf/       OKF v0.2 spec and conformance helpers — the format definition, 
                implementation guides, and status notes (e.g., why log.md deviates 
                from §9). Machine-readable specs; human-editable status/rationale.

docs/tasks/     OKF v0.2 task concepts — BDD test scenarios, task breakdowns, 
                scenario descriptions. Each file MUST have frontmatter with type 
                field per OKF §11. Current convention: type='Executable Task'.

sources.json    The ONE provenance ledger, keyed by source_id (e.g. 
                CONF-SN-405143554, JIRA-SN-41). For every upstream page/issue: 
                local version, which raw/ file holds it, which wiki/ artifacts cite 
                it, and whether it has drifted from upstream (`stale` field). 
                Regenerated by bin/generate-ledger.py; stale is refreshed by 
                bin/check-staleness.sh (the only script in this pipeline that makes 
                a network call for this purpose).

bin/            The toolchain — fetch, ingest, generate, validate, gate, doctor.
                - bin/okf-freshness.py: OKF v0.2 freshness reporter (§5.5 
                  stale_after age + §5.3 provenance staleness + trust tier)
                - bin/okf-validate.py: OKF v0.2 conformance validator (§11 
                  frontmatter checks; excludes *.recompiled.md sidecars)
                - bin/okf-coverage.py: Coverage/completeness detector — 
                  reports MISSING (source elements absent from artifact) and 
                  UNSOURCED (artifact elements not in any source) per element 
                  type. Producer convention, not OKF requirement.
                - Three legacy ingest/generate scripts (pre-OKF pipeline)
```

No `.kb/index/` directory exists here. `sources.json` at the repo root is 
the single provenance ledger — the five-file scheme was dropped as redundant.

## OKF v0.2 — the format this wiki uses

All `docs/wiki/` artifacts and `docs/tasks/` concepts conform to **OKF v0.2** 
(Open Knowledge Format). The spec is at [`docs/okf/OKF-SPEC-v0.2.md`](docs/okf/OKF-SPEC-v0.2.md).

Three key differences from the pre-OKF schema:

| Pre-OKF | OKF v0.2 |
|---|---|
| No standardized `type` field | REQUIRED: `type:` field in all non-reserved files (§11) |
| Staleness: `stale` in sources.json only | First-class: `stale_after:` (§5.5) + `generated: {by, at}` (§5.2) + `verified: []` (§5.3) both in the artifact |
| Trust implicit in upstream_refs | Explicit: `verified: {by, at}` records who/when verified; absent means **unverified** (§5.3) |

### `docs/raw/` frontmatter — full contract

See `docs/raw/SCHEMA.md` for the authoritative version; summary:

| Field | Required when | Meaning |
|---|---|---|
| `source` | always | `confluence` \| `jira` |
| `origin` | always | `ingested` \| `derived` |
| `title` | always | Page/issue title (drives the filename slug) |
| `fetched_at` | always | When this snapshot was pulled |
| `layer` | always | Always `raw` for files in this directory |
| `page_id` | `origin: ingested` | Confluence numeric page ID, or Jira issue key. Canonical identity. |
| `space_key` | `origin: ingested` | Confluence space key or Jira project key |
| `version` | `origin: ingested` | Confluence page version, or epoch-seconds of Jira's `fields.updated` |
| `url` | `origin: ingested` | Canonical web URL |
| `parent_id` | optional | Confluence hierarchy parent, when the API provides one |

### `docs/wiki/` frontmatter — OKF v0.2 reference

OKF v0.2 field meanings per **§2 (Terminology)**, **§5 (Trust & Freshness)**, **§6 (Provenance)**, **§11 (Conformance)**:

| Field | Required | OKF § | Meaning |
|---|---|---|---|
| `type` | yes | §11 | String identifying the concept type (e.g. `'Feature Specification'`, `'API Reference'`, `'Test Scenario'`). Unknown types are allowed (§11). Do not confuse this with `artifact_type` in the legacy schema. |
| `artifact_id` | yes | §6 | Citation handle, e.g. `WIKI-SN-AUTH-001` — stable across file renames (use this, not filename) |
| `upstream_refs` | no | §6 | List of source_ids this concept was compiled from (e.g. `['CONF-SN-405143554']`). Parsed as block-list (`- item`) or inline (`[item, ...]`). Enables §5.5 provenance staleness check. |
| `generated` | no | §5.2 | `{by: "claude/opus-5", at: "2026-07-27T00:00:00Z"}` — who generated this artifact and when. Enables §5.3 freshness check. |
| `verified` | no | §5.3 | `{by: "human:alice", at: "2026-07-27"}` — who verified (person or agent) and when. Absent means **unverified** (not unknown, genuinely unverified — this is honest current state for all 21 artifacts as of 2026-07-28). |
| `stale_after` | no | §5.5 | ISO 8601 date when this artifact should be re-verified (e.g. `'2026-10-28'`). When today >= stale_after, it's stale by policy. All 21 artifacts use 90-day horizon: `'2026-10-28'`. |
| `topic` | optional | — | List of keywords — searched by `query-wiki`. Free-form; not OKF-standardized. |
| `sources` | optional | — | List of `{title, url}` — human-readable fallback links (not authoritative; upstream_refs is the record). Not OKF-standardized. |
| Other fields | optional | §11 | Extra keys are allowed (§11). confidence_markers, artifact_type, project_id, role, etc. are supported but not required. |

**Key OKF v0.2 rule:** `verified` field's absence is NOT the same as unknown 
trust. Absence means the artifact has never been verified. The value of an absent 
field is **unverified**, which is the honest current state and should never be 
papered over. (This fixes the pre-OKF conflation of "I haven't checked" with 
"I've checked and it's good".)

### `docs/tasks/` frontmatter — task concepts in OKF v0.2

Task files (BDD scenarios, task breakdowns, scenario specifications, etc.) MUST conform to OKF §11:

- Required: `type:` field — current convention is `'Executable Task'` for all task files (descriptive, self-explanatory per §4.1)
- Required: valid YAML frontmatter (balanced braces/brackets)
- Optional: all other fields (unknown types allowed, extra keys allowed)
- Optional but recommended: `generated: {by, at}` to record who last edited the file and when

**Current status (2026-07-28):** 6/6 files under `docs/tasks/auth/` conform to OKF §11:
- `US5-01-happy-path.md` — covers US5 happy path, 9 AC items
- `US5-02-anti-enumeration.md` — email enumeration guard
- `US5-03-reset-link-expired.md` — expired token handling
- `US5-04-token-consumed.md` — single-use token validation
- `US5-05-resend-cooldown.md` — cooldown between email resends
- `US5-06-rate-limit.md` — rate limiting on password-reset endpoint

Each has ~10-20 AC items related to password-reset flow, plus figma links, infrastructure scope, and references to raw API specs.

**Task lifecycle vs. concept lifecycle:** Task files use `status: todo | in_progress | done | blocked` to track executable work. This is a **separate axis** from OKF §5.4 concept lifecycle (`status: draft | stable | deprecated`). The task `status` field is a producer extension — it records work state, not spec maturity. Do not add §5.4 `status` to task files; the distinction is already unambiguous from context and adding both would conflate axes. 

### `origin: ingested` vs `origin: derived`

- **`ingested`** — a fetched snapshot of a real upstream page/issue. All 192 
  `docs/raw/` files are `ingested`. Required fields: `page_id`, `space_key`, 
  `version`, `url`.
- **`derived`** — synthesized by an agent from other knowledge, with no 
  single upstream page to point `page_id`/`url`/`version` at. None yet in 
  `docs/raw/`, but `digest-wiki` produces `docs/wiki/` equivalents with 
  `upstream_refs: []` standing in for the missing provenance.

A `derived` artifact is never reported as an orphan for lacking 
`page_id`/`url`, and is always skipped by staleness checks (no upstream 
version to compare).

## Sidecar convention (producer convention, §3.1)

Files matching `*.recompiled.md` are review working copies or intermediate artifacts, not published concepts. They are automatically excluded from bundle concept counts by `bin/okf-validate.py`. A sidecar MAY carry `type` and other OKF frontmatter fields (since it is still a markdown file with frontmatter), but it is not counted in conformance metrics or publication counts.

Example: `docs/wiki/auth/auth-overview.recompiled.md` is a review sidecar for `auth-overview.md`, automatically excluded from the 21-artifact count.

## Freshness and staleness

Per OKF v0.2 §5:

1. **§5.5 policy staleness:** Compare today's date to `stale_after:` in the 
   artifact. If today >= stale_after, it is **stale by policy**. Run 
   `python3 -sS bin/okf-freshness.py` to report this across all 21 artifacts.

2. **§5.3 provenance staleness:** Compare the artifact's `generated.at` to the 
   git commit date of each file listed in `upstream_refs`. If any raw file is 
   newer than `generated.at`, the artifact is **stale by provenance** — its 
   sources have moved ahead. `okf-freshness.py` reports this; 21/21 artifacts 
   are stale by provenance as of 2026-07-28 (all generated 2026-07-27, all 
   raw files committed today).

3. **§5.3 trust tier:** 
   - **unverified** (absent `verified` field) — 21/21 artifacts as of 2026-07-28
   - **machine-confirmed** (verified by agent, no human: prefix)
   - **human-reviewed** (verified by human: person/account prefix)

All three are facts. Lack of verification is not a bug; it is the honest 
current state.

## Citation convention

Always cite by `artifact_id` (or `page_id` for a `docs/raw/` file) plus the 
upstream URL and version, e.g.:

> Per `WIKI-SN-AUTH-001` (upstream: CONF-SN-405143554, v12) —
> https://ipas-tech.atlassian.net/wiki/spaces/SN/pages/405143554

For OKF artifacts, also state the trust tier and stale status:

> Per `WIKI-SN-AUTH-001` (CONF-SN-405143554 v12, stale-by-provenance, 
> unverified) — https://...

Never cite a bare filename — filenames are cosmetic and not stable 
across renames.

## Which tool answers which question

| Question | Tool |
|---|---|
| "What do we know about X?" (read-only) | `query-wiki` |
| "Deep dive / compare / timeline, save it" | `digest-wiki` |
| "Pull this Confluence page/space in" | `pull-confluence` |
| "Pull this Jira issue in" | `pull-jira` |
| "Create/update/transition/comment/link a Jira issue" | `jira-write` |
| "Is this wiki artifact still accurate?" (check stale status) | `python3 -sS bin/okf-freshness.py` or `query-wiki` to read sources.json stale field |
| "Do all artifacts conform to OKF v0.2?" | `python3 -sS bin/okf-validate.py docs/wiki` (21/21 conformant, 1 sidecar excluded) |
| "Do task concepts have type fields?" | `python3 -sS bin/okf-validate.py docs/tasks` (6/6 conformant) |
| "Does an artifact cover what its sources contain?" (coverage/completeness) | `python3 -sS bin/okf-coverage.py docs/wiki/profile/profile-api-overview.md` (single) or `python3 -sS bin/okf-coverage.py docs/wiki/**/*-overview.md` (bulk summary) — reports MISSING (in source not artifact) and UNSOURCED (in artifact not in sources) per element type; scoped `coverage_exclusions` may use `applies_to: missing|unsourced` and `element: '*'` for intentional overview omissions |
| "Run coverage self-test" | `python3 -sS bin/okf-coverage.py --self-test` (7 assertions on element extraction and frontmatter parsing) |
| "Run the self-tests" | `python3 -sS bin/okf-freshness.py --self-test` and `python3 -sS bin/okf-validate.py --self-test` |
