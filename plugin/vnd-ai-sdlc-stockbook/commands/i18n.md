# /i18n $ARGUMENTS

Extract hard-coded user-facing strings to the slang translation files
(`lib/i18n/<locale>.json`) and update call sites to use the generated
`AppLocale` accessors.

## Steps

1. Scope: `$ARGUMENTS` slug or the whole diff if omitted.
2. Scan for hard-coded user-facing strings (text in widgets, dialogs,
   snackbars, exception messages that reach the UI).
3. For each finding, propose:
   - key (camelCase, <= 30 chars, namespaced by screen — e.g.
     `feedComposerHint`)
   - value per locale defined in `slang.yaml` (`base_locale` first).
4. Update every `lib/i18n/<locale>.json` atomically — keep the key set
   identical across locales.
5. Replace call sites with the generated slang accessor (e.g.
   `t.feedComposerHint` after `import 'package:.../i18n/i18n.g.dart'`).
6. Regenerate via `dart run slang` (or the project's build_runner
   script).
7. Report: keys added, keys reused, files touched.

## Refuse

- Strings inside `domain/` (should never have user copy).
- String concatenation like `'Hello, ' + name` — convert to an ICU
  placeholder (`'feedGreeting'` with `{name}`).
