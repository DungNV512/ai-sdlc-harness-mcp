# Problem Statement Canvas template

`schema: vnd.ai-sdlc.problem-statement-canvas/v1`

The A2 artefact, and the one everything downstream is measured against. One
A4 page. The page limit is the point: a problem that needs three pages to
state has not been framed yet, it has been described.

Written for the **root** problem. If the canvas lists five symptoms, A2 is not
finished — go back and find what they are symptoms of.

```markdown
# Problem Statement — <short handle>

- **From**: Idea Card <link>
- **Working session**: <date> with <the person who raised it>
- **Owner**: <PM>

## WHO

<Which specific people. A role and a rough number, not "users". If it is
several groups, say which one hurts most — a canvas that spreads evenly
across four audiences usually has not found the root problem.>

## WHAT

<What happens today, and what it costs. Behaviour and consequence, still no
solution. Numbers where they exist; `[ước tính]` on the ones that are
estimates.>

## WHY IT MATTERS

<The consequence if nothing changes. Tie it to something the business already
cares about and already measures — revenue, risk, churn, headcount, a
regulatory obligation. "It is inefficient" is not a consequence.>

## WHY NOW

<What makes this the right quarter rather than any of the last eight. A
deadline, a contract, a platform change, a competitor move, a cost that has
crossed a threshold. If the honest answer is "nothing in particular", write
that — it is a legitimate finding and G1 needs to hear it.>

## Root problem hypothesis

<One sentence. This is what A3 tests and what G1 rules on.>

## Explicitly out of scope

<What this is not about. Cheap to write here, expensive to argue about
later.>
```

## DoD

Someone with no involvement in the project reads it and can answer:

> Whose problem is this, when does it happen, and how much does it hurt?

Test it on an actual person before A3. If they hesitate on any of the three,
the canvas is not done — and the fix is always cutting, never adding.
